## Authority and world continuity

- One server-thread `TraceStorageManager` in `storage/TraceLiveStorage.kt` owns live shard state, indexes, note commands and completion application. One `TraceIoCoordinator` **per server** serializes immutable archive I/O across dimensions. The old storage manager, deferred journal and separate annotation-echo SavedData are test-only legacy fixtures, **not** alternate shipping authorities.
- The new root is `world/data/better_player_traces/`, marked `better-player-traces-v4`; dimension shards live below `<namespace>/<dimension>/`. A populated unversioned or incompatible root is refused with an error, **not** imported, reset or deleted. Manifest/backup-only candidates are discovered; checksummed revisioned snapshots retain one prior recoverable publication. There is no automatic migration or promised compatibility with old populated trace worlds. Before deploying into any valued world, preserve a backup and explicitly resolve an incompatible root; never silently discard it.
- Reads distinguish `Present`, proven `Absent`, `Loading`, `Unavailable`, `Corrupt` and `Unsupported`. Unknown data must not be interpreted as empty or used to prune records. The server owns revisions and applies only completed publications, not an older whole-shard snapshot over newer live changes. Dirty/inflight shards stay pinned. Queue reservations cover count and bytes before admission; one shard has a 64 MiB encoded headroom limit. The default queued-I/O cap is 64 tasks and 128 MiB, with separate dirty-byte accounting.
- A footprint accepted into live memory can still be lost on a crash before the scheduled approximately 20-tick flush. Disk failure pauses admission: incidental captures may be **omitted** with aggregate diagnostics, never silently queued without capacity; unrecorded erosion is not applied. Recovery retries are paced and must resolve the accepted authority before admission resumes. Shutdown stops new admission and reports unresolved writes after its bounded drain, rather than racing a second writer.
- Annotation create/update/delete, including optional echo and deletion receipt, stage privately with request identity and expected revision where applicable. A `Committed` result is issued only after proven durable publication. `Pending` is not success; `Indeterminate` is not a definite rejection and must keep the draft/authority for reconciliation. Old committed notes remain visible until a replacement publishes. Connection/dimension-scoped responses and retained drafts prevent a late reply from mutating a new session. `DeathTraceSavedData` and the separate arena-duel archive API remain independent.

## Gameplay, queries and client

- Capture preserves distance/strength/owner/support and arrival/departure semantics. A segment has bounded emissions; teleport, discontinuity or omitted capture breaks the sequence. Surviving trace IDs and sequence indices are never renumbered. Loaded **Minecraft chunks**, not the archive cache, determine support/rain maintenance; the resumable work neither loads terrain nor applies invented offline rain catch-up. Environmental/support erasure physically removes the trace from ID, tile, support and time indexes.
- Local/probe queries use local shards and actual dimension height. Archive-wide strength/percentile summaries rebuild through bounded cursors and expose readiness; `globalReady=false` is **not** evidence of zero global traffic. Guidance route work, contiguous-run gap handling and XP observation advance on server ticks independently of reveal polling; stale/partial routes cannot award XP. Public `TraceQueryApi` callers should request bounded local regions; an unavailable shard is not an empty successful query.
- Network protocol is `better_player_traces_v11` (both ends must match). Latest request parameters coalesce per connection; players rotate fairly, tiles start nearest-first. A resumable metadata selector examines tiles and notes under the same streaming visit quotas, maintains exact bounded top-K annotation priority/distance ordering, and validates note/archive pins before **complete** publication. Typed unavailable metadata retains the previous complete response. A moved player may finish a coherent old-anchor selection and immediately queue the newer center. Existing death pool/echo data retain their separate configured overall caps.
- Trace tiles transfer in at most **512-record pages**, pinned to a revision and shard incarnation; a changed revision/record count or unsafe cursor incarnation restarts rather than mixing pages. The client replaces a tile only after all pages of a strictly newer generation/revision arrive. An unavailable-tile status marks last-confirmed data stale without erasing it; a proven eviction removes it. Client pending assemblies and clip/geometry caches are bounded. Unchanged frames reuse the flattened trace view and decoded clips, and only affected footprint cells rebuild; existing frustum/distance rendering remains. These are source properties, not visual validation.

## Provisional defaults and visibility

| Budget (server config unless stated) | Default |
| --- | ---: |
| Client radius / server maximum | 16 / 32 chunks |
| Examined stream tiles | 64/player/tick; 512/server/tick |
| Examined trace/metadata records | 4,096/player/five ticks; 4,096/server/tick |
| Actual encoded tile/status/eviction traffic | 512 KiB/player/five ticks; 1 MiB/server/tick |
| Pinned transfer/metadata reservations | 8 MiB/player; 64 MiB/server |
| Queued archive I/O | 64 tasks; 128 MiB |
| Live shard cache / trace page | 128 shards / 512 records |

The encoded-byte quota above applies to **tile/status/eviction packets**; the separate, pre-existing count-capped metadata response is not charged to that byte quota. The record quota counts examined work, including metadata selection, rather than only emitted traces. Budgets and client assembly headroom are safety/admission choices, **not** demonstrated latency, throughput, memory or player-count guarantees. A dense tile can still take multiple ticks and significant client memory. Aggregate stream diagnostics report saturation, unavailable reads, transfer/metadata age and encoded bytes; archive backlog exposes reserved count/bytes, and client diagnostics report cache rebuild time and clip-decode reuse. These are not latency measurements; avoid per-record logging. There is no density erasure or LOD used to satisfy a limit.
