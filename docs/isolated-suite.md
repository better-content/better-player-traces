## Freeze, receipts and no-overwrite rules

- `scripts/qualification/suite.json` is the declarative tier and numeric-gate manifest. `scripts/qualification/receipt.py freeze --tier TIER --task-graph PATH [--config PATH] [--world NEW_PATH]` records commit, tracked/untracked input hashes, provider hash, Java/Forge/KFF, CPU/RAM/GPU probe and explicitly observed renderer, config hashes and an audited task graph. Performance additionally requires `--old-source CHECKOUT --no-traces CHECKOUT` in **different repositories**. Existing v3 data must never enter a v4 world; the no-Traces world is different again. The script does **not** run anything or authorize a run.
- Freeze outputs one `build/qualification/attempts/<UUID>/input.json`, with `FROZEN_UNRUN` and `approved=false`. `verdict` creates one no-overwrite `verdict.json` only after operator review and an actual separate tier-specific human approval reference. It requires evidence files and never decides that missing evidence is a pass. Keep the exact command, task graph, source/provider/config/world hashes, process logs, screenshots, fault point, raw metrics, and rejected attempts together. Do not reuse failed worlds or overwrite logs.
- An optional read-only performance assessment is `python3 scripts/qualification/assess_performance.py EVIDENCE.json --output NEW.json`. Its `numeric_eight_actor_gate_only` is **not** overall acceptance. Missing parity/samples yields `inconclusive`; 16/32 never yield a supported-player claim. Review material baseline regressions even if absolute gates pass.

## Real clients: supervised evidence, not mock acceptance

Extend the existing ForgeGradle export via `-PtracesTwoClients=true -PtracesObservationFixture=true -PtracesFixtureRoot=<attempt>/native` plus the existing `scripts/visual-validation/export-observation-launches.gradle`. `launches.json` then contains separate `runClientA`/`runClientB` commands with distinct offline usernames/UUIDs and game directories. The separate runner requires a frozen `two-client` attempt, a prepared `server/server.properties` with `online-mode=false` and `level-name=world`, and `--approval-reference`. It refuses an existing world on `--stage initial`; `--stage restart` requires the **same disposable** `server/world` and the earlier stage's receipt. It retains server and both client logs, independent screenshot paths and world-file hashes. It never automatically calls a log, screenshot or a console echo a gameplay PASS; operator must verify two actual connected clients from their own logs and capture evidence. A timeout/missing client or unexpected exit is inconclusive. Server stop is graceful; process interruption belongs to the fault tier only.

Supervised scenarios to record explicitly: simultaneous capture/visibility and note create/edit/delete + draft state, echo playback, disconnected/dimension-late replies, loaded-chunk rain and unloaded exclusion, death/respawn, arrival/departure, reconnect and cold restart. Capture per-client reveal/occlusion, labels, GUI, route guidance and frame-sensitive video/stills for human review. Optional Quark/Zeta/shaders and nonshipping echo prototype are excluded. The runner does **not** automate those interactions; a nonempty screenshot directory is not acceptance.

## Performance evidence contract and gate

Collect one `runs[]` JSON row for each candidate `redesigned`, `pre-redesign`, `no-traces`, case and actor count; each row supplies `candidate`, `actors`, `case`, `seed`, `workloadSha256`, `sourceManifestSha256`, `worldSchema` (`v4`, `v3`, `none` respectively), distinct `worldPath`, `serverLog`, `clientALog`, `clientBLog`, `renderer`, `realClients` (at least two), `syntheticActors` and unique `syntheticActorIds`, `warmupSeconds`, `steadySeconds`, `heapObservationSeconds`, `tpsWindowSeconds:60`, 20 or more steady `tps` windows, `tickMs`, `healthyDurableNoteMs`, `clientFrameMs:{a:[],b:[]}`, `postGcHeapMiB:[start,end]`, `budgetViolations:[]`, `outageIntervals:[]`, and `gcBookendInLatencySamples:false`. All numeric samples must be finite and nonnegative. Append measured queue age, pinned bytes, encoded stream bytes, examined work, revision restarts, stale duration, CPU/RAM/GPU/JVM and GC-pause series and exact limit-sweep repetitions to raw evidence even though the small assessor cannot derive them. Keep every raw sample, not only percentiles.

Required normal cases are `dispersed-clear`, `dispersed-rain`, `dense-clear`, `dense-rain`, `cold-read-reconnect`, `long-save`, with identical fresh seeds/workload scripts across three distinct candidate worlds; no v3/v4 data sharing. At radius 16 use 8 actors (two **real** clients and six explicitly synthetic), ≥10m warm-up, ≥20m steady per case, ≥100 healthy durable-note completions overall and a separate ≥30m post-GC heap observation. Numeric bounds: every 60s TPS window ≥19; tick p95 ≤50ms and p99 ≤100ms; healthy note p95 ≤5s and p99 ≤15s; each real client's frame p95 ≤50ms; no configured reservation violation; post-GC floor growth ≤max(128MiB, 10% of start). Exclude GC bookend collections from latency windows; outage notes belong to the fault tier. Compare against **both** retained baselines and investigate material regressions; don't label limits calibrated from one case. Repeat core work at 16 and 32 as **diagnostic curves only**. Synthetic actors cannot stand in for actual joined-client evidence.

**Unimplemented performance prerequisites:** deterministic 8/16/32 actor/workload driver, client frame and packet collectors with trusted timestamps, server tick/heap/queue/GC sampler, baseline deployment/isolation checks and repeated limit-sweep runner. `assess_performance.py` does not generate this evidence and cannot qualify capacity by itself. Do not call an empty or hand-constructed JSON a benchmark result.

## Failure and release boundary

All selected assertions must pass on frozen bytes. Missing receipts, stale/partial XP, note/echo split, false durable ACK, unknown-as-empty, wrong-world mutation, save loss, crash and over-budget work are failures/inconclusive, never a pass. Preserve failed attempts. Fixes require a newly frozen source/provider/config input and the affected gates rerun **after fresh approval**. This source work does not authorize deployment, staging, a pack-facing JAR, commit or publication.
